## Executive Summary

- **管理后台定位为“集中管理工作台”。** 它承接手机不擅长的批量商品维护、盘点、纠错、经营分析、员工权限、基础设置和数据导入导出。
- **后台 MVP 优先解决数据治理，不做大型 ERP。** 首期包含经营看板、商品中心、库存中心、采购/销售记录、经营分析、员工权限、基础设置和审计日志；复杂采购审批、多门店和专业财务后置。
- **所有高风险动作必须可追溯。** 商品以停用代替随意删除，库存以流水和修正单变化，历史销售与收支使用作废/冲正，不允许直接覆盖历史事实。
- **后台与小程序共享自有服务端。** 当前已部署 Node.js API、MySQL、Nginx、`storeId` 成员模型与 revision 兼容层；后台开发前继续完成网页鉴权、细粒度实体、事务、权限和旧数据迁移。

### 当前技术基线

| 层级 | 方案 |
| --- | --- |
| 公网入口 | 自有云服务器 Nginx，生产使用备案 HTTPS 域名 |
| API | Node.js 18 + systemd，统一前缀 `/api/v1` |
| 数据库 | 自有 MySQL 8.0，不开放公网端口 |
| 小程序身份 | 服务端用微信 code 换 OpenID，再签发本系统会话 |
| 后台身份 | 独立网页登录与权限会话，禁止复用微信端令牌 |
| 迁移阶段 | `store_states` JSON + `revision` 兼容层，随后拆分细粒度业务表 |

## 1. 产品定位与目标

### 1.1 一句话定位

为小型服装与化妆品门店提供一套适合电脑操作的商品、库存、人员和经营数据管理后台。

### 1.2 核心目标

1. 店主可批量创建、筛选和维护商品与规格。
2. 月底盘点能够形成盘点单、差异清单和确认记录。
3. 每笔库存变化、销售纠错和收支冲正都可追溯到操作者与原因。
4. 店主可配置员工角色，控制成本、盈利、库存修正和导出权限。
5. 可按日期、业务类型、商品和收款方式查看经营分析并导出。

### 1.3 非目标

- 首期不做完整会计总账、税务和净利润核算。
- 首期不做顾客会员、营销、商城和在线订单。
- 首期不做多门店调拨和复杂仓储。
- 首期不做复杂采购审批与供应商应付账款。
- 首期不替代微信开发者工具的发布与版本管理。

## 2. 用户与权限

| 角色 | 使用后台的主要目的 |
| --- | --- |
| 店主 | 查看全店经营、维护商品、管理库存、配置成员与权限、导入导出 |
| 管理员 | 执行商品、库存和日常运营管理；敏感能力由店主授权 |
| 财务 | 查看销售、成本、盈利和其他收支，执行冲正与报表导出 |
| 店员 | 默认不进入后台；如开放，只能查看被授权的商品或参与盘点 |

权限按“角色默认值 + 成员例外授权”计算，至少区分查看、创建、编辑、停用、修正、导出和权限管理。

## 4. 全局框架与通用能力

### 4.1 页面框架

- 左侧一级导航，顶部包含店铺切换、全局搜索、通知、当前用户。
- 页面标题下方放本页筛选与主要动作。
- 列表支持保存筛选条件，但 MVP 不要求自定义复杂视图。
- 桌面宽度优先适配 1280px 及以上，同时保证 1024px 可用。
- 窄屏只保证查看与简单操作，不把后台重新做成另一套手机端。

### 4.2 全局搜索

支持按商品名称、系统编号、货号、供应商和业务单号搜索，并按结果类型分组。

### 4.3 通知中心

展示：

- 待确认库存差异。
- 低库存、缺货和临期提醒。
- 导入完成或失败。
- 权限变更与成员邀请。
- 数据冲突和关键同步异常。

### 4.4 列表通用规范

- 支持搜索、条件筛选、排序、分页和列显示控制。
- 批量操作前展示影响数量。
- 高风险操作要求二次确认并填写原因。
- 导出遵循当前筛选条件，并记录导出人、时间与数据范围。

## 5. 模块功能需求

### 5.1 经营看板

#### 顶部摘要

- 今日销售额、经营盈利、销售笔数、售出数量。
- 当前库存件数、库存成本、低库存规格、临期商品。
- 与昨日或上月同期比较；比较基准必须明确。

#### 内容区

- 近 7 天收入与盈利趋势。
- 今日服装/化妆品销售构成。
- 待处理库存差异和数据异常。
- 最近高风险操作。

#### 权限

无成本或盈利权限的用户不展示对应指标、趋势和导出。

### 5.2 商品中心

#### 商品列表

字段建议：

- 勾选框、图片、商品名称、系统编号、货号。
- 业务类型、分类、规格数、总库存。
- 成本价、参考售价、供应商/品牌。
- 库存状态、商品状态、更新时间。

筛选建议：业务类型、分类、状态、库存状态、供应商/品牌、更新时间。

#### 新建/编辑商品

- 通用字段：名称、分类、编号、货号、图片、成本价、参考售价、位置、低库存阈值。
- 服装字段：供应商、颜色、尺码。
- 化妆品字段：品牌、批次号、到期日期、色号、容量/规格。
- 使用规格矩阵批量生成组合并填写初始库存。
- 规格组合上限默认 200，超过时要求拆分或导入。
- 保存前展示新增、保留和将停用的规格数量。

#### 批量操作

- 批量修改分类、供应商/品牌、阈值和状态。
- 批量导入商品与规格。
- 批量导出当前结果。
- 不允许通过批量编辑直接覆盖库存；库存变化进入库存中心。

#### 商品停用与删除

- 有业务记录的商品只能停用，历史记录永久保留快照与关联。
- 从未发生业务且库存为 0 的误建商品，店主可永久删除。
- 商品编号创建后保持稳定，不因停用或删除其他商品而重排或复用。

### 5.3 库存中心

#### 实时库存

- 按商品与规格展示系统库存、可售库存、库存成本、状态和最近变动。
- 筛选业务类型、分类、库存状态、供应商/品牌、货位。
- 可导出当前库存快照。

#### 盘点单

1. 创建盘点单并选择业务范围。
2. 生成盘点基准快照。
3. 店员在手机或后台录入实际库存。
4. 系统展示系统数、实盘数、差异和差异金额。
5. 店主/管理员确认差异，事务性生成库存修正流水。
6. 盘点单完成后不可直接编辑，只能发起补充修正。

#### 库存修正

- 必填商品、规格、目标库存或变化量、原因。
- 显示修正前后库存和成本影响。
- 超过后台配置阈值时需要二次审批或店主确认。
- 禁止删除已生效修正；错误修正使用反向冲正。

#### 库存流水

支持按日期、商品、规格、业务类型、来源单据、操作者和终端筛选，并显示变更前、变化量、变更后和原因。

### 5.4 采购与供应商

#### 拿货记录

- 日期、商品、规格、数量、单价、总额、供应商、操作人、备注。
- 按日/月/供应商汇总采购数量与采购支出。
- 错误记录通过作废/冲正处理，不直接删除。

#### 供应商档案

- 名称、联系人、电话、备注、状态。
- 关联商品数、累计拿货次数和金额。
- 重名供应商支持合并，合并前展示影响记录。

首期不包含采购审批、应付账款和付款核销。

### 5.5 销售与收支

#### 销售记录

- 日期、业务单号、商品、规格、数量、单价、总额、成本、毛利、收款方式、操作人。
- 支持日期、业务类型、商品、操作人和收款方式筛选。
- 无成本权限时隐藏成本和毛利列。

#### 销售纠错

- 未发生退款时可作废整笔销售并恢复库存。
- 退货生成独立退货/冲正记录，关联原销售。
- 必须填写原因，保留原记录，不允许覆盖历史单价、成本和数量。

#### 其他收入/支出

- 记录类型、金额、业务归属、日期、备注、附件和操作人。
- 错误记录使用冲正；列表显示原记录、冲正记录和当前有效状态。

### 5.6 经营分析

#### 筛选

- 业务类型：全部、服装、化妆品。
- 时间：今日、昨日、本月、上月、自定义区间。
- 商品、分类、收款方式和操作人。

#### 指标

- 销售收入、已售商品成本、商品毛利、经营盈利、毛利率。
- 销售笔数、售出数量、平均每单。
- 数据完整性：缺失成本的销售笔数与金额。

#### 分析内容

- 7 天、30 天和 12 个月趋势。
- 每日收入、成本与盈利明细。
- 商品毛利、销量和毛利率排行。
- 亏损商品清单。
- 收款方式金额和占比。
- 导出当前筛选范围的报表。

盈利口径固定为：

```text
商品毛利 = 销售收入 - 已售商品成本
经营盈利 = 商品毛利 + 其他收入 - 其他支出
```

不得把经营盈利称为净利润。

### 5.7 员工与权限

#### 成员管理

- 邀请成员、查看邀请状态、重新发送或取消邀请。
- 修改姓名、角色、数据范围和账号状态。
- 停用后服务端立即拒绝新的访问令牌和写请求。

#### 权限项

- 商品：查看、编辑、停用、导入导出。
- 库存：查看、盘点录入、确认、修正、导出。
- 采购/销售：查看、新增、作废/冲正、导出。
- 财务：查看成本、查看盈利、录入收支、冲正收支。
- 系统：员工管理、基础设置、审计日志。

权限更改必须记录变更前后值。店主角色不可被普通管理员降级或停用。

### 5.8 基础设置

- 商品分类：服装与化妆品分别维护，支持排序、停用和合并。
- 品牌与供应商：统一基础资料，表单只选择有效项。
- 库存规则：默认低库存阈值、差异审批阈值。
- 收款方式：启用、停用和排序。
- 提醒规则：提醒类型、接收角色和频率。
- 编号规则：新商品使用稳定编号，禁止因删除其他商品自动重排。

### 5.9 操作日志

- 记录操作者、角色、店铺、来源终端、动作、对象、时间和请求 ID。
- 高风险操作保存变更前后摘要、原因和关联单据。
- 支持按人、动作、对象和日期筛选。
- 普通业务流水与安全审计日志分开存储，审计日志不可由前端删除。

## 6. 核心业务流程

### 6.1 首次批量建账

```text
下载商品模板 → 填写商品和规格 → 上传文件 → 字段校验
→ 预览新增/更新/错误行 → 确认导入 → 查看导入结果
```

库存初值作为“期初库存”业务单据写入流水，不直接修改余额。

### 6.2 月底盘点

```text
创建盘点单 → 选择范围 → 冻结盘点基准
→ 手机/后台录入实盘数 → 查看差异 → 填写差异原因
→ 确认生效 → 生成修正流水与盘点报告
```

盘点期间是否阻止销售需由业务决定；MVP 默认不阻止销售，而是在确认时重新计算期间变化并提示冲突。

### 6.3 销售纠错

```text
查找原销售 → 发起作废/退货 → 填写原因与数量
→ 显示库存和金额影响 → 有权限者确认
→ 生成关联冲正记录 → 更新库存与有效销售汇总
```

### 6.4 员工入店

```text
店主创建邀请 → 选择角色与权限 → 员工微信登录接受
→ 建立 store_members 关系 → 员工按权限使用小程序
```

## 7. 数据、接口与安全要求

### 7.1 核心实体

- `stores`、`users`、`store_members`。
- `products`、`product_specs`、`categories`、`brands`、`suppliers`。
- `inventory_balances`、`inventory_operations`、`stocktakes`。
- `purchases`、`sales`、`sale_reversals`、`finance_entries`。
- `settings`、`audit_logs`、`imports`、`exports`。

### 7.2 写入规则

1. API 从登录会话获取用户，从请求读取 `storeId`，校验成员关系与权限。
2. 商品、销售、采购和库存分别提供细粒度接口，不再整包覆盖 `state`。
3. 使用事务保证业务记录、库存流水和库存余额一起成功或一起失败。
4. 使用版本号实现乐观并发控制；旧版本修改返回冲突。
5. 写接口接受幂等请求 ID，防止重复提交。
6. 审计日志由服务端生成，前端不可伪造操作者和时间。

### 7.3 数据导入导出

- 上传前明确模板版本、允许字段和最大行数。
- 导入分为校验、预览、确认三个阶段。
- 错误行提供可下载的错误说明，不允许部分静默丢失。
- 导出异步生成，文件具有有效期和权限校验。
- 导出内容不包含 OpenID、访问令牌等身份或安全字段。

## 8. 旧数据迁移

1. 对现有 `store_states` 做只读备份和结构校验。
2. 为每个旧账号创建目标 `store` 和店主成员关系。
3. 依次迁移商品、规格、采购、销售、收支和库存流水。
4. 根据迁移后的流水和余额做总库存、销售收入、成本与盈利核对。
5. 迁移验收后切换小程序到新 API；旧数据保留只读回滚窗口。

迁移时应为旧商品保留一个稳定的外部编号，不再因为删除其他商品重排编号。

## 9. 状态与异常处理

| 场景 | 处理方式 |
| --- | --- |
| 并发编辑商品 | 拒绝旧版本保存，展示冲突字段并要求刷新 |
| 库存余额变化 | 盘点/修正确认前重新校验最新库存 |
| 导入存在错误 | 显示错误行；用户明确选择全部取消或导入有效行 |
| 权限刚被收回 | 当前页面可提示，下一次接口调用立即拒绝 |
| 导出生成失败 | 保留筛选条件并允许重试，不产生空文件 |
| 商品有历史记录 | 禁止永久删除，改为停用 |
| 操作部分失败 | 事务回滚并展示可追踪的请求 ID |

## 10. 原型覆盖范围

本轮可点击原型重点覆盖：

- 经营看板与侧边导航。
- 商品中心列表、筛选、批量选择和编辑抽屉。
- 库存中心的实时库存、盘点与修正入口。
- 经营分析的趋势与商品表现。
- 员工权限与基础设置页面。

原型用于验证信息架构和关键交互，不连接真实 MySQL 生产数据，也不代表最终视觉稿。

## 11. 验收标准

### 11.1 功能

- 店主可以批量维护商品，但不能通过商品批量编辑直接覆盖库存。
- 有业务记录的商品无法永久删除，只能停用。
- 盘点、库存修正、销售纠错和收支冲正都生成关联记录。
- 成本、盈利、导出和权限管理均受服务端权限控制。

### 11.2 数据与安全

- 手机与后台写入同一数据源且不存在最后写入整包覆盖。
- 所有库存变化可追溯到采购、销售、盘点或修正单。
- 高风险动作记录操作者、原因、时间、来源终端和变更前后值。
- 越权调用、重复提交和旧版本覆盖均被服务端阻止。

### 11.3 体验

- 1280px 下商品和库存表格可完成主要操作，1024px 下不丢失关键字段与动作。
- 列表、表单、抽屉、确认对话框具备加载、空数据、错误和无权限状态。
- 主要操作支持键盘导航，表格和表单具备可识别标签。
