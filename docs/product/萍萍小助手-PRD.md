## 2. 产品概述

萍萍小助手是一款面向小型实体店的轻量库存经营工具，帮助店主在手机上完成服装与化妆品的商品建档、库存增加、售出扣减、记录查询和盈利分析。

产品强调操作简单、数据清楚和移动端易用，不建设线上商城，也不替代专业财务软件。首期重点解决以下问题：

1. 商品款式多，颜色、尺码、容量和色号容易记错。
2. 进货和售出后没有及时记账，实际库存不清楚。
3. 服装与化妆品字段不同，混在同一套表单中难以使用。
4. 店主无法快速知道今天卖了多少、赚了多少、哪些商品缺货或临期。
5. 换手机后本地数据容易丢失，需要微信账号登录和自有服务器同步。

## 3. 产品目标

### 3.1 核心目标

- 店主可在 1 分钟内完成一次商品创建、库存增加或售出登记。
- 服装按“商品 + 颜色 + 尺码”管理独立库存。
- 化妆品按“商品 + 款式/色号 + 容量/规格”管理独立库存。
- 首页 5 秒内看懂当前库存、今日销售、今日盈利和待关注事项。
- 服装与化妆品的商品、记录和盈利可分别查看。
- 使用微信身份登录，实现同一小程序内的多设备服务器同步。
- 删除商品后，不再出现在商品列表、统计和最近变动中。

### 3.2 首期成功指标

| 指标 | 目标 |
| --- | --- |
| 商品创建成功率 | ≥ 98% |
| 进货/增加库存提交成功率 | ≥ 99% |
| 售出登记成功率 | ≥ 99% |
| 云登录成功率 | ≥ 98% |

### 3.3 首期不包含

- 顾客商城、购物车、在线支付和订单配送
- 会员、积分、优惠券和营销活动
- 多门店调拨
- 完整财务会计、税务和净利润核算
- 供应商对账和采购审批
- 扫码枪、标签打印机和小票打印
- 自动生成补货采购单
- 独立库存盘点模块

## 6. 核心业务流程

### 6.1 首次使用

打开小程序 → 微信账号登录 → 自有 API 换取会话 → 拉取服务器数据 → 服务器无数据时上传本机已有数据 → 进入首页。

规则：

- 微信 OpenID 只用于识别用户，服务端通过 `store_members` 确认用户可访问的 `storeId`。
- 服务器存在数据时优先使用服务器数据。
- 网络异常但本机存在已登录会话时，可保留本地数据并提示重试同步。
- 登录失败时不得生成虚假的默认账号。

### 6.2 新建服装

服装页 → 新建服装 → 先填写名称、分类和至少一个规格 → 创建商品 → 进入商品详情或编辑页继续完善图片、价格、供应商、位置和其他规格。

服装规格不使用全店统一尺码。每个商品独立维护自己的颜色和尺码，例如：

- 商品 A：黑色 / S、M、L
- 商品 B：蓝色 / 26、27、28
- 商品 C：均码

### 6.3 新建化妆品

化妆品页 → 新建化妆品 → 填写名称和分类即可先创建 → 可选展开色号与容量、图片与更多资料 → 填写各规格库存 → 保存。未展开规格时自动创建“通用 / 标准规格 / 库存 0”，后续可继续完善。

化妆品不使用“登记进货”文案，统一使用“增加库存”和“库存记录”。

### 6.4 增加库存

- 服装：首页“登记进货” → 选择服装 → 选择颜色/尺码 → 填写数量和进价 → 保存。
- 化妆品：首页“增加库存”或化妆品页入口 → 选择商品与规格 → 填写增加数量 → 保存。

库存增加后必须同时更新规格库存、库存记录、当日经营汇总和服务器数据。

服装拿货时必须填写拿货数量和单件拿货价，系统实时计算本次拿货总额。拿货记录展示每次拿货的数量、单价、总额、供应商和日期，并汇总今日与本月拿货总额。商品详情展示当前平均拿货价和“当前库存 × 平均拿货价”计算出的当前库存成本；盈利页中的成本统一称为“已售商品成本”，避免与采购支出和剩余库存成本混淆。

### 6.5 登记售出

首页“登记售出” → 选择服装或化妆品 → 选择商品与规格 → 填写数量、售价、收款方式和备注 → 确认售出。

系统必须校验库存充足，扣减对应规格库存，并保存售出时的单位成本，保证历史盈利不会因以后进价变化而改变。

### 6.6 修改错误库存

商品详情 → 编辑商品 → 在对应规格中直接填写正确库存数字 → 保存修改。

- 不使用大型“删除库存”按钮。
- 不弹出多余的二次说明提示。
- 只允许填写大于或等于 0 的整数。
- 修改后保存一条“编辑商品库存”记录。

### 6.7 删除商品

商品中心 → 查询删除资格 → 仅店主对零库存且无任何经营历史的误建商品执行二次确认 → 永久删除。

有库存、销售、采购、库存操作或业务审计的商品禁止永久删除，只能停用。永久删除成功后：

- 不出现在商品列表和搜索结果中。
- 不计入商品款数、库存、低库存和缺货统计。
- 不出现在首页最近变动中。
- 不删除销售、采购、库存操作和审计历史；有这些历史的商品在资格检查阶段即被拒绝。

## 7. 功能需求

### 7.1 微信登录与自有服务器同步（P0）

登录页展示：

- 店主名称和可选头像。
- 微信身份识别说明。
- 自有服务器库存同步说明。
- 本地缓存保护说明。
- 微信账号登录按钮。
- 登录或同步失败的明确错误信息。

同步规则：

- 本地操作立即写入缓存，不等待网络返回。
- 数据修改后合并延迟约 500 毫秒上传自有 API。
- 登录时先拉取服务器数据；服务器为空时上传本机数据。
- 服务器写入失败不能删除本地已确认数据，并保留待重试状态。
- 每次写入携带 `revision`；旧版本请求返回 409，不允许静默覆盖较新数据。

### 7.2 首页（P0）

首页采用经营看板布局，展示：

- 问候语、日期和单店库存管理说明。
- 当前库存总件数与库存成本。
- 服装、化妆品分类库存卡片。
- 今日销售额、今日盈利和今日售出件数。
- 商品款数、低库存规格、已缺货数量。
- 临期化妆品和低库存商品的合并关注列表。
- 最近三条有效库存变动。

交互要求：

- 点击服装/化妆品卡片进入对应管理页。
- 点击商品款数进入商品汇总。
- 点击低库存规格或已缺货进入合并后的库存状态列表。
- 点击关注项或最近变动进入有效商品详情。
- 首页“登记进货/增加库存”和“登记售出”必须先区分服装与化妆品。
- 首页不提供库存盘点快捷入口。

### 7.3 服装管理（P0）

服装页需要：

- 展示服装库存总数、商品款数和今日售出。
- 支持按名称、真实货号或内部流水号搜索。
- 显示商品图片、名称、真实货号、规格数量和库存状态；内部流水号作为次要信息。
- 提供新建服装、售出、库存记录入口。
- 不重复提供首页已有的“登记进货”入口。
- 使用与首页一致的水滴衣架图标，不在衣架旁混入化妆品图标。

### 7.4 化妆品管理（P0）

化妆品页与服装页保持同一布局体系，但使用独立字段和文案：

- 分类：护肤、彩妆、香水、洗护、其他。
- 字段：品牌、批次号、到期日期、款式/色号、容量/规格。
- 快捷入口：增加库存、售出、库存记录、售出记录。
- 不显示“登记进货”文案。
- 新建化妆品按钮文案为“新建化妆品”。
- 保存按钮文案简洁，不出现重复的“保存库存”表达。
- 常用色号和容量采用点选标签；新输入的品牌保存后自动加入常用品牌列表。

### 7.5 商品档案（P0）

通用字段：

| 字段 | 服装 | 化妆品 | 规则 |
| --- | --- | --- | --- |
| 商品名称 | 必填 | 必填 | 去除首尾空格 |
| 分类 | 必填 | 必填 | 仅用于筛选，不影响内部流水号 |
| 内部流水号 `code` | 自动 | 自动 | 系统生成且创建后不可修改，例如 `0001`；不作为真实货号 |
| 货号 `itemNumber` | 可选 | 可选 | 吊牌、进货单或供应商货号，最多 80 字符；不含条码职责 |
| 商品图片 | 可选 | 可选 | 支持相册和拍照 |
| 成本价/进价 | 可选 | 可选 | ≥ 0，最多两位小数 |
| 参考售价 | 可选 | 可选 | ≥ 0，最多两位小数 |
| 供应商 | 可选 | 不显示 | 服装专属 |
| 品牌 | 不显示 | 可选 | 化妆品专属 |
| 批次号 | 不显示 | 可选 | 化妆品专属 |
| 到期日期 | 不显示 | 可选 | 化妆品专属 |
| 颜色 | 必填 | 不适用 | 服装规格维度 |
| 尺码 | 必填 | 不适用 | 服装规格维度 |
| 款式/色号 | 不适用 | 可选 | 为空时使用“通用” |
| 容量/规格 | 不适用 | 按需 | 展开规格时必填；快速创建默认“标准规格” |

修改商品资料或删除其他商品均不会改变已有 `code`；删除后的 `code` 不复用，编号序列只递增。

规格组合一次最多生成 40 个，防止误输入造成大量无效规格。

编辑商品必须支持：

- 修改商品图片和基础资料。
- 增加或删除颜色、尺码、色号和容量。
- 修改每个规格的库存数字。
- 保留未删除规格原有库存。
- 新增规格默认库存为 0。

### 7.6 库存状态（P0）

库存状态定义：

- 正常：库存大于低库存阈值。
- 偏低：库存大于 0 且小于或等于阈值。
- 缺货：库存等于 0。

低库存规格和已缺货应在同一列表中展示，可按服装/化妆品筛选，不建设重复的库存提醒页面。

### 7.7 售出管理（P0）

售出记录包含：

- 业务类型（服装/化妆品）
- 商品名称与商品编号快照
- 规格文本
- 售出数量
- 单件售价与总金额
- 售出时单位成本
- 收款方式
- 备注、操作人和时间

收款方式：微信、支付宝、现金、银行卡、未记录。

规则：

- 数量必须为正整数。
- 售出数量不能超过当前库存。
- 售出后库存不得小于 0。
- 删除商品后，历史售出记录仍可用于盈利计算。

### 7.8 盈利分析（P0）

盈利页面必须将服装与化妆品分开，顶部提供业务切换。

页面默认只展示盈利合计、销售收入、商品成本、售出数量、毛利率、销售笔数和平均每单；趋势、每日记录、商品排行及收款构成统一收进“经营明细”，由用户按需展开。

每个业务分别展示：

- 今日、昨日、本月、上月和自定义日期。
- 销售收入、已售商品成本、盈利金额和毛利率。
- 与上一周期的金额和百分比对比。
- 7 天、30 天和 12 个月趋势。
- 每日收入、成本和盈利。
- 盈利最高、销量最高、毛利率最高和亏损商品排行。
- 各收款方式金额和占比。
- 补录额外收入或支出，并可删除错误补录记录。

计算规则：

```text
商品毛利 = 销售收入 - 已售商品成本
毛利率 = 商品毛利 ÷ 销售收入 × 100%
经营盈利 = 商品毛利 + 补录收入 - 补录支出
```

补录页面先选择“额外收入”或“额外支出”，金额始终填写正数，由系统自动处理加减；再选择服装/化妆品、发生日期和可选备注。正常登记售出产生的盈利不得重复补录。

盈利属于商品毛利口径，不扣除房租、水电、工资和税费，不得称为净利润。

### 7.9 我的（P1）

- 展示店主名称、微信身份和云同步状态。
- 展示商品款数和库存总数。
- 支持查看账号与安全说明。
- 支持复制库存表格数据并粘贴到 Excel。
- 支持退出登录，但退出不删除本地或服务器经营数据。
- 预留员工与权限、供应商、分类设置入口。

### 7.10 分享、体验和发布（P0）

- 首页和商品详情页支持微信分享卡片。
- 分享标题使用产品名称或商品名称，不包含敏感库存成本。
- 体验版仅允许管理员、开发者和体验成员打开。
- 正式发布后，普通微信用户才能通过分享卡片正常打开。
- 发布流程：开发者工具上传 → 后台设为体验版 → 真机验收 → 提交审核 → 发布。

## 8. 数据模型

### 8.1 商品 Product

核心字段：

- `id` / `productId`、`adminProductId`、`specId`：系统内部关联 ID
- `code`：系统生成的内部流水号，创建后稳定、不可复用
- `itemNumber`：店主维护、AI 只读识别图片可见内容的真实货号，可空
- `businessType`：`clothing` 或 `cosmetics`
- `name`、`category`、`image`
- `costPrice`、`salePrice`
- `supplier`、`brand`、`batchNumber`、`expiryDate`
- `lowStockThreshold`
- `specs[]`
- `createdAt`、`updatedAt`

### 8.2 规格 Spec

- `id`
- `color`：服装颜色；化妆品款式/色号或“通用”
- `size`：服装尺码；化妆品容量/规格
- `stock`

### 8.3 库存记录 Operation

- `type`：入库、出库或编辑修正
- `businessType`
- `productId`、`productName`
- `specId`、规格快照
- `quantity`、`beforeStock`、`afterStock`
- `reason`、`operator`、`createdAt`

### 8.4 售出记录 Sale

- 商品、规格和业务类型快照
- 数量、售价、总金额和售出时单位成本
- 收款方式、备注、操作人和时间

### 8.5 自有 MySQL 迁移兼容层

表：`store_states`

- 主键为 `store_id`，用户与店铺关系由 `users`、`stores`、`store_members` 表维护。
- `state` 暂存当前小程序完整店铺状态，`revision` 用于乐观并发控制。
- 该表用于从单机版本平滑迁移，不作为后台最终业务模型。
- 管理后台正式开发时逐步拆分为商品、规格、库存余额、库存流水、采购、销售和收支等细粒度表。

## 9. 自有云服务器与账号架构

| 项目 | 配置 |
| --- | --- |
| 小程序客户端 | 微信原生小程序，`wx.request` 调用 REST API |
| 公网入口 | 已备案 HTTPS 域名 + Nginx `/api/` |
| API 服务 | Node.js 18，systemd 常驻，绑定 `127.0.0.1:3000` |
| 数据库 | MySQL 8.0，绑定 `127.0.0.1:3306` |
| 核心接口 | `/api/v1/auth/wechat/login`、`/session`、`/store/state`、`/health` |

安全要求：

- AppSecret、MySQL 密码和 JWT 密钥只保存在服务器受限环境文件中。
- 服务端调用微信 `jscode2session`，客户端不能直接获得 AppSecret。
- 所有数据读写经过 API，会话必须校验用户、店铺成员关系和角色。
- MySQL 与 Node.js 端口不对公网开放，公网只允许 Nginx 80/443。
- 正式发布必须使用备案域名和有效 HTTPS，并配置微信 request 合法域名。

## 10. 视觉与交互规范

### 10.1 视觉方向

- 整体采用雾感蓝粉渐变背景。
- 卡片使用半透明白色、柔和描边和轻阴影。
- 使用适量水滴、水纹和水元素，不影响文字阅读。
- 品牌图标为水滴与衣架组合。
- 服装页沿用水滴衣架图标；化妆品页使用独立化妆品图标。
- 主色以雾蓝、柔粉和深蓝文字为主，警告使用橙色，危险使用红色。

### 10.2 交互要求

- 同级页面颜色、圆角、间距和阴影保持一致。
- 主按钮不过度放大，避免笨重和“工具软件感”。
- 修改库存以直接数字输入为主。
- 可点击统计卡片必须有箭头、按压态或其他明确反馈。
- 空状态提供下一步入口，不展示虚构演示数据。
- 删除属于危险操作，使用小尺寸文字按钮或更多菜单，并进行二次确认。

## 11. 异常处理

| 场景 | 处理要求 |
| --- | --- |
| 微信身份获取失败 | 显示 API 返回的可理解提示，不生成假账号 |
| API 初始化失败 | 提示检查服务器地址、HTTPS、域名白名单和服务状态 |
| 服务器同步失败 | 保留本地数据，允许重新同步 |
| 未创建商品即售出 | 引导先创建对应业务商品 |
| 库存不足 | 阻止提交并显示当前库存 |
| 商品被删除 | 记录页不跳转详情，统计自动排除 |
| 规格库存不是非负整数 | 阻止保存并定位错误规格 |
| 图片失效 | 显示业务类型默认图标 |
| 到期日期早于当天 | 显示已过期危险状态 |

## 12. 非功能要求

- 支持常见 iPhone 和 Android 微信版本。
- 常用列表在 500 个商品规模内保持流畅。
- 所有金额最多保留两位小数。
- 所有库存写操作必须可追溯。
- 页面异常退出后，已确认操作不得丢失。
- 服务器写入失败不得覆盖较新的本地状态；版本冲突必须重新拉取后处理。
- 图片后续应迁移到自有对象存储或服务器文件服务，数据只保存 HTTPS 地址或文件 ID。
- 正式发布前完成隐私保护指引、服务类目和小程序备案要求。

## 14. 验收标准

### 14.1 登录与服务器同步

- 自有 API 能用微信 `code` 换取正确 OpenID 并签发短期会话。
- 首次登录可将本机数据上传服务器。
- 同一微信在另一台设备登录后能读取同一店铺数据。
- 旧 revision 写入被拒绝，不会覆盖较新服务器状态。

### 14.2 商品与规格

- 服装可为不同商品设置不同尺码。
- 化妆品可不填色号；快速创建使用“标准规格”，展开规格后可点选或补充容量。
- 创建后可继续修改图片、资料和规格。
- 规格库存可直接修改为非负整数。
- 删除商品后首页最近变动不再展示该商品。

### 14.3 库存与售出

- 服装进货正确增加目标规格库存。
- 化妆品增加库存不出现“登记进货”文案。
- 售出正确扣减库存并阻止负库存。
- 商品款数、低库存和缺货统计均可点击查看。

### 14.4 盈利

- 服装与化妆品盈利互不混合。
- 收入、成本、盈利和毛利率计算正确。
- 修改商品当前进价不改变历史售出盈利。
- 删除错误补录记录后所有汇总立即更新。

### 14.5 真机与发布

- 管理员和体验成员可扫码打开体验版。
- 体验版微信登录、商品创建、售出和重启恢复均正常。
- 首页和商品详情可生成有效分享卡片。
- 正式版提交审核前无阻断错误和测试数据。
