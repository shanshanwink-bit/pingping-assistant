# 萍萍小助手微信云开发部署

代码已经接入微信 OpenID 登录与云数据库同步。发布前需要在微信开发者工具完成以下一次性配置。

## 1. 共享云环境

公开仓库不包含真实 AppID 或云环境 ID。请先把 `project.config.json` 中的 `appid` 改为自己的小程序 AppID，再在 `utils/cloud-config.js` 中填写当前项目 AppID。若使用同主体环境共享，还需填写资源方 AppID 与云环境 ID；不使用共享环境时保持这两个字段为空，并按需填写 `envId`。

使用共享环境时，资源方需要在微信开发者工具“云开发 → 设置 → 扩展能力 → 环境共享”中授权当前项目 AppID。客户端会通过 `wx.cloud.Cloud` 初始化共享环境；未配置共享环境时则使用普通的 `wx.cloud.init`。

## 2. 创建数据库集合

在云开发控制台的数据库中创建集合：

```text
store_states
```

集合权限设置为“所有用户不可读写”。小程序端不直接访问集合，所有读写都经过 `store-sync` 云函数。旧 AppID 继续使用原有 `store_<OpenID>` 文档以保留历史数据；新 AppID 使用 `store_<AppID>_<OpenID>` 文档，两个小程序的数据互不混用。

## 3. 上传云函数

在微信开发者工具中分别右键以下目录，选择“上传并部署：云端安装依赖”：

- `cloudfunctions/login`
- `cloudfunctions/store-sync`
- `cloudfunctions/cloudbase_auth`

部署前，将 `cloudfunctions/cloudbase_auth/index.js` 中的两个 AppID 占位符，以及 `cloudfunctions/store-sync/index.js` 中的资源方 AppID 占位符，替换为自己的真实值。部署完成后，在云函数控制台确认三个函数均为正常状态。`cloudbase_auth` 只允许配置中的 AppID 访问共享资源。

## 4. 首次登录与迁移

1. 重新编译小程序，进入“微信账号登录”页面。
2. 点击微信账号登录。
3. 如果该 OpenID 在云端没有店铺数据，当前设备已有的商品、库存、销售和盈利数据会自动上传。
4. 如果云端已有店铺数据，则优先下载云端版本并替换本机缓存。

## 5. 验证

登录后新增一个测试商品，再到云数据库 `store_states` 集合查看对应 `store_...` 文档。文档内的 `state.products` 应包含该商品，`updatedAt` 会随业务修改更新。

## 当前同步策略

- 本地缓存立即保存，页面操作不等待网络。
- 修改后 500 毫秒合并并同步一次云端，避免连续操作产生大量请求。
- 每个来源 AppID 与微信 OpenID 的组合对应一个独立店铺文档。
- 同一账号多设备同时编辑时采用最后一次写入的数据；正式多人协作版本应进一步改为分集合、事务和角色权限模型。
