# 商品档案治理 v1.2.x 隔离测试数据库验收方案

## 1. 安全边界

- 仅允许使用新建的、名称和连接信息均明确标识为测试用途的 MySQL 8.0 数据库。
- 禁止复用生产数据库账号、生产库名、生产备份挂载点或生产 API 环境文件。
- 执行前记录测试库主机、端口、库名和账号；四项中任一项无法确认时立即停止。
- 测试数据必须为人工构造的虚拟商品与交易，不复制真实顾客、员工或经营数据。
- 本文是验收步骤，不授权自动执行迁移、部署或任何生产写入。

## 2. 字段职责

- 内部关联：`productId`、`adminProductId`、`specId`，只用于数据库与交易关联。
- 真实货号：`itemNumber` / `item_number`，可空，最多 80 字符，来自吊牌、进货单或供应商。
- 兼容字段：`code`，系统生成的内部流水号，创建后不可修改、不可重排、不可复用。
- `item_number_managed`：区分“历史数据尚未受控”与“用户已主动维护（包括显式清空）”，不代表货号是否存在。
- AI 只能提取图片中明确可见的真实货号，不得生成内部 ID 或内部流水号。

## 3. 环境准备

1. 创建独立测试库和最小权限测试账号，确认连接目标不属于生产环境。
2. 保存空库备份或可重复创建脚本。
3. 依次执行现有基础迁移 `001` 至 `007`，核对无报错。
4. 准备三件虚拟商品：无历史商品、有采购历史商品、待停用商品；为每件商品建立对应 `store_states.products` 映射。
5. 启动仅连接该测试库的 Node 与 Go 测试实例，使用独立端口和测试密钥。

## 4. 迁移验收

1. 执行 `008_admin_product_item_number.sql`。
2. 确认 `admin_products.item_number` 为 `VARCHAR(80) NULL`，存在普通索引 `(store_id, item_number)`，不存在唯一约束。
3. 确认旧商品 `item_number IS NULL`，且 `code`、库存、销售、采购和流水均未变化。
4. 执行 `009_admin_product_item_number_managed.sql`。
5. 确认 `item_number_managed` 为 `TINYINT(1) NOT NULL DEFAULT 0`，迁移未回填 `item_number`、未修改经营记录。
6. 确认迁移文件执行顺序为 `008` 后 `009`；旧版本程序忽略新增列时仍可读取原有字段。

## 5. 功能验收清单

1. **老商品兼容**：读取 `item_number = NULL`、`item_number_managed = 0` 的商品，货号保持为空，不从 `code` 伪造。
2. **新建真实货号**：创建商品并填写前后带空格的货号，保存值应去除首尾空格，`code` 由系统生成。
3. **修改真实货号**：编辑 `itemNumber` 后，MySQL、Node 商品目录和小程序同步值一致，`code` 不变。
4. **显式清空**：将货号清空后，`item_number = NULL`、`item_number_managed = 1`；下一次目录同步清除旧 JSON 货号。
5. **停用商品**：停用后 Web 状态、Node/Go 当前状态与小程序目录一致，普通可交易列表和普通 AI 候选均排除。
6. **重新启用**：重新启用后恢复卖货、拿货和普通 AI 匹配，并存在状态变更审计。
7. **安全删除成功**：零库存、零历史、无处理中 AI 入库引用的误建商品仅由 owner 删除；`store_states.products` 与 `admin_products` 在同一事务中均消失。
8. **安全删除拒绝**：为商品创建采购历史后请求永久删除，必须返回 `409 PRODUCT_HAS_HISTORY`，商品和全部历史仍存在。
9. **删除不重排**：删除中间商品后，其他商品 `code` 与删除前完全一致。
10. **删除编号不复用**：删除商品后再创建商品，新 `code` 必须来自继续递增的 `nextProductNumber`，不得取得已删除值。
11. **停用交易拦截**：Node 与 Go 的卖货、拿货/入库入口均拒绝已停用商品，库存与交易表不发生部分写入。
12. **AI 真实货号匹配**：图片识别 `productCode` 与启用商品 `itemNumber` 原值一致时优先匹配；同货号多商品时只返回候选。
13. **AI 停用匹配**：真实货号只命中停用商品时返回 `inactive_match`，不绑定内部 ID、不允许确认入库、不建议创建同货号商品。
14. **回归**：执行 Node 全量测试、Go 测试/构建、Admin 构建和小程序静态检查，并人工核对卖货、拿货、批量采购、编辑、停用和删除。

## 6. 并发与回滚验收

- 在只读删除资格接口返回 `canDelete: true` 后，同时发起一笔交易和 DELETE；重复执行多轮，验证两者只能一个成功。
- 人为让删除审计写入失败，验证 `store_states` 和 `admin_products` 删除、revision 更新均回滚。
- 人为让批量采购中间一行失败，验证整批库存和采购记录均回滚。
- 验收失败时停止后续步骤，保留测试日志与请求 ID；不要通过手工改表伪造通过结果。

## 7. 验收记录与清理

验收记录至少包含：测试库连接目标（不含密码）、迁移校验结果、每项用例的请求 ID/响应码、关键前后快照、自动测试输出和失败项。

验收完成后关闭测试实例。测试库按团队保留策略整库归档或删除；清理前再次确认目标是隔离测试库，绝不对生产库执行清理命令。
