# 萍萍小助手自有云服务器部署说明

本文只保留正式环境后续维护所需的目录、职责、环境变量、迁移、发布和回滚规则。一次性部署记录、截图和验收报告不进入仓库。

## 1. 正式环境

| 项目 | 当前配置 |
| --- | --- |
| 操作系统 | Ubuntu 24.04 LTS |
| Web | `https://shanshanwink.online/pingping/` |
| Node API | `https://shanshanwink.online/pingping-api/v1` |
| Go API | `https://shanshanwink.online/pingping-admin-api/v1` |
| Node 目录 | `/opt/pingping-assistant-api` |
| Go 目录 | `/opt/pingping-admin-api` |
| Web 目录 | `/var/www/pingping` |
| 商品图片 | `/var/lib/pingping-admin-api/product-images` |
| 环境文件 | `/etc/pingping-assistant-api.env` |
| 数据库 | MySQL 8.0，`pingping_assistant` |

Nginx 是唯一公网入口。Node、Go、MySQL 分别只监听 `127.0.0.1:3000`、`127.0.0.1:3001`、`127.0.0.1:3306`，不得在安全组或 UFW 中开放这些端口。

外部正式路径由 Nginx 重写到服务内部路径：

| 用途 | 外部路径 | 内部路径 |
| --- | --- | --- |
| 小程序 API | `/pingping-api/v1/` | `/api/v1/` |
| 管理后台 API | `/pingping-admin-api/v1/` | `/admin-api/v1/` |
| Web | `/pingping/` | `/var/www/pingping/` |

旧路径只用于迁移兼容，不得作为新配置继续传播。

## 2. 服务职责

- `server/`：Node 小程序 API、微信/Demo 会话、状态同步、商品目录、卖货/拿货事务和 AI 辅助流程。
- `server-go/`：Go 管理 API、Web 会话、商品/库存/经营数据、员工权限、安全删除和审计。
- `admin/`：Vue 3 Web 静态站点。
- `server/migrations/`：Node 与 Go 共用的 MySQL 迁移。
- `server/nginx/`、`server/systemd/`、`server-go/systemd/`：正式配置模板。

## 3. 环境变量

首次安装从 `server/.env.example` 和 `server-go/.env.example` 核对字段，在服务器创建 `/etc/pingping-assistant-api.env`。文件建议权限为 `root:www-data 640`。

主要字段：

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=pingping_assistant
MYSQL_USER=...
MYSQL_PASSWORD=...
JWT_SECRET=...
WECHAT_APP_ID=...
WECHAT_APP_SECRET=...
PRIMARY_STORE_ID=...
WECHAT_ALLOWED_OPENIDS=...
ADMIN_ORIGINS=https://shanshanwink.online
PRODUCT_IMAGE_DIR=/var/lib/pingping-admin-api/product-images
DASHSCOPE_API_KEY=...
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_VISION_MODEL=qwen3.7-plus
AI_REQUEST_TIMEOUT_MS=60000
```

Demo 默认关闭。启用时必须填写独立 Demo 店和 clerk 用户：

```dotenv
DEMO_LOGIN_ENABLED=true
DEMO_STORE_ID=...
DEMO_USER_ID=...
DEMO_TOKEN_TTL_SECONDS=7200
```

`DEMO_STORE_ID` 不得等于真实 `PRIMARY_STORE_ID`，`DEMO_USER_ID` 必须在该 Demo 店中处于 active clerk 状态。修改环境文件后只重启受影响服务并重新检查健康状态。

AppSecret、MySQL 密码、JWT Secret、DashScope Key、真实 OpenID、生产账号密码和私钥不得写入仓库、文档、日志或发布包。

## 4. MySQL 与迁移

全新环境按文件编号从 `001_initial.sql` 顺序执行到 `009_admin_product_item_number_managed.sql`，不得跳号或改写历史迁移。

- `008_admin_product_item_number.sql`：增加可空真实货号和普通索引，不回填旧 `code`。
- `009_admin_product_item_number_managed.sql`：记录货号是否由用户显式维护，包括显式清空。

正式生产库已经执行 008 和 009，不得重复执行。部署普通代码和文档时不运行迁移。任何未来迁移必须先说明目的、影响、备份和回滚方式，经确认后再执行。

备份至少覆盖 MySQL、商品图片目录、Go 二进制、Node 发布目录和 Web 静态目录。数据库备份必须定期验证可恢复性。

## 5. 发布前检查

```bash
# 根目录
node --test tests/*.test.js

# Node
cd server
pnpm run check

# Web
cd ../admin
pnpm build

# Go
cd ../server-go
gofmt -l .
go test ./...
go build ./...
```

同时检查 `git diff --check`、敏感信息、变更文件和迁移范围。小程序页面变化还需在微信开发者工具编译；不得向生产门店写测试交易。

## 6. 最小发布范围

- 仅文档变化：不部署生产服务。
- 小程序代码变化：提交 GitHub 后在微信开发者工具上传体验版；服务器无对应变化时不重启服务。
- Node 变化：备份 `/opt/pingping-assistant-api`，只替换必要文件，保留环境文件与依赖锁定，重启 `pingping-assistant-api`。
- Go 变化：构建目标二进制，备份并替换 `/opt/pingping-admin-api/pingping-admin-api`，重启 `pingping-admin-api`。
- Web 变化：备份 `/var/www/pingping`，发布 `admin/dist/` 内容。普通 Web 发布不修改 Nginx。
- 数据库或 Nginx 只有在明确需要且已获确认时修改；008/009 不重复执行。

## 7. 健康检查

```bash
systemctl is-active mysql
systemctl is-active pingping-assistant-api
systemctl is-active pingping-admin-api
systemctl is-active nginx

curl -fsS http://127.0.0.1:3000/api/v1/health
curl -fsS http://127.0.0.1:3001/admin-api/v1/health
curl -fsS https://shanshanwink.online/pingping-api/v1/health
curl -fsS https://shanshanwink.online/pingping-admin-api/v1/health
curl -fsSI https://shanshanwink.online/pingping/
```

健康结果必须为 `ok: true`、数据库 `connected`；Node 还应显示微信鉴权已配置。生产只做只读健康检查，不创建测试销售或采购。

## 8. 回滚

1. 停止受影响服务或暂停静态文件切换。
2. 恢复本次发布前备份的 Node 目录、Go 二进制或 Web 静态目录。
3. 保留 `/etc/pingping-assistant-api.env`，除非本次明确变更了环境文件且已有独立备份。
4. 重启受影响服务并执行内部、外部健康检查。
5. 数据库迁移只按预先确认的回滚方案处理；不得通过删除表、字段或手工改经营数据回滚应用代码。
6. 记录回滚版本、原因和健康检查结果。

Nginx 如确需变更，必须先备份配置，执行 `sudo nginx -t` 成功后才能 reload；普通应用发布不修改 Nginx。

## 9. 微信体验版与审核版

正式域名、HTTPS 和微信合法域名已完成。仓库中的 `project.config.json` 保持可公开的基线，本机真实 AppID 差异只保留在本地，不提交。

最终流程：微信开发者工具编译 → 上传代码 → 微信公众平台设为体验版 → 生成体验二维码并真机验收 → 按需提交审核。上传前确认 Demo 店可用、正式审核所需 AI 开关状态正确，并再次检查没有测试数据或敏感配置进入代码包。
