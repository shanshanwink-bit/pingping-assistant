# 萍萍小助手自有云服务器部署说明

## 1. 当前部署基线

| 项目 | 当前方案 |
| --- | --- |
| 云服务器 | Ubuntu 24.04 LTS |
| Web 入口 | Nginx 80/443 |
| API | Node.js 18 小程序 API + Go 管理后台 API |
| 数据库 | MySQL 8.0，库名 `pingping_assistant` |
| API 目录 | `/opt/pingping-assistant-api` |
| 环境变量 | `/etc/pingping-assistant-api.env` |
| 健康检查 | `/api/v1/health` |

MySQL 只监听 `127.0.0.1:3306`，Node.js 只监听 `127.0.0.1:3000`，Go 只监听 `127.0.0.1:3001`；公网仅由 Nginx 提供 HTTPS 入口。不要在安全组或 UFW 中开放 3000、3001、3306。

正式路径和迁移期兼容路径如下：

| 用途 | 正式路径 | 迁移期旧路径 |
| --- | --- | --- |
| Node 小程序 API | `/pingping-api/v1/` | `/api/v1/` |
| Web 管理后台 | `/pingping/` | `/admin/` |
| Go 管理 API | `/pingping-admin-api/v1/` | `/admin-api/v1/` |

Nginx 将正式 Node 路径重写到内部 `/api/v1/`，将正式 Go 路径重写到内部 `/admin-api/v1/`。`/xiaofu/` 与 `/xiaofu-api/v1/` 当前只做 404 隔离预留，不得代理到萍萍服务。

## 2. 仓库结构

- `server/src/`：REST API、鉴权、数据读写与版本冲突处理。
- `server/migrations/`：MySQL 结构迁移。
- `server-go/`：管理后台登录、员工权限与业务读取 API。
- `server/systemd/`：API 常驻服务配置。
- `server/nginx/`：Nginx HTTP 反向代理示例。
- `utils/server-config.js`：小程序 API 地址。
- `utils/server-sync.js`：登录、拉取、推送与本地重试。

项目不再依赖腾讯云开发、云函数或云数据库。

## 3. 服务器环境变量

首次部署从 `server/.env.example` 创建 `/etc/pingping-assistant-api.env`。生产文件权限建议为 `root:www-data 640`，至少包含：

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=pingping_assistant
MYSQL_USER=pingping_api
MYSQL_PASSWORD=在服务器生成的随机密码
JWT_SECRET=至少32字符的服务器随机密钥
WECHAT_APP_ID=真实小程序AppID
WECHAT_APP_SECRET=真实小程序AppSecret
PRIMARY_STORE_ID=管理后台账号所属店铺ID
WECHAT_ALLOWED_OPENIDS=允许访问该店铺的微信openid，多个用英文逗号分隔
ADMIN_ORIGINS=https://后台域名
DASHSCOPE_API_KEY=由运维人员在服务器安全配置
QWEN_VISION_MODEL=qwen3.7-plus
AI_REQUEST_TIMEOUT_MS=60000
```

AppSecret、MySQL 密码、JWT 密钥、DashScope API Key 与真实 openid 不得提交到 Git，也不要粘贴进产品文档或群聊。`QWEN_VISION_MODEL` 未设置时默认使用 `qwen3.7-plus`。生产环境应显式配置 `AI_REQUEST_TIMEOUT_MS=60000`（单位为毫秒），为视觉请求保留合理响应时间；调整该值不改变 AI Feature Flag。`PRIMARY_STORE_ID` 与 `WECHAT_ALLOWED_OPENIDS` 必须同时配置，确保小程序与管理后台读取同一店铺，同时阻止未授权微信账号访问经营数据。修改后执行：

```bash
sudo systemctl restart pingping-assistant-api
curl -fsS http://127.0.0.1:3000/api/v1/health
```

健康检查中的 `database` 应为 `connected`；填写微信配置后 `wechatAuthConfigured` 应为 `true`。

## 4. MySQL 初始化

1. 创建 `pingping_assistant` 数据库。
2. 创建仅允许 `127.0.0.1` 登录的 `pingping_api` 用户。
3. 仅授予该库所需的读写与迁移权限，不使用 MySQL root 运行 API。
4. 按编号顺序执行 `server/migrations/001_initial.sql` 至 `007_admin_product_code_sequence.sql`，不得跳号或重复执行。
5. `002_admin_mvp.sql` 含历史原型看板、任务、风险和商品示例数据。历史迁移不得改写；全新正式环境执行迁移后，应在首次开放前按明确主键核对并删除这些原型行，不得用模糊条件清理真实经营数据。
6. 备份策略至少包含每日数据库备份、异地保留和定期恢复演练。

当前 `store_states` 是迁移兼容层：数据属于 `storeId`，写入带 `revision`，可阻止旧版本静默覆盖。后台进入正式业务开发后，再逐步迁移到商品、规格、库存流水、采购、销售和收支等细粒度表。

## 5. Nginx 与 systemd

部署前备份原配置；更新 Nginx 后必须先执行 `sudo nginx -t`，成功后才能 reload。服务状态检查：

```bash
systemctl is-active mysql
systemctl is-active pingping-assistant-api
systemctl is-active nginx
sudo ss -lntp
```

预期只有 80/443 对公网监听，3000 与 3306 仅监听回环地址。

## 6. 微信正式发布前置条件

微信小程序正式版不能长期使用裸 IP 的 HTTP 接口。发布前必须：

1. 准备已完成 ICP 备案的域名并解析到服务器。
2. 为 API 域名配置有效 HTTPS 证书并启用 443。
3. 把 `utils/server-config.js` 的 `apiBaseUrl` 改为 `https://你的域名/api/v1`。
4. 在微信公众平台将该 HTTPS 域名配置为 request 合法域名。
5. 将 `project.config.json` 中的 AppID 改为真实小程序 AppID。
6. 在服务器环境变量中直接填写同一小程序的 AppID/AppSecret，重启 API。
7. 将开发期间的“不校验合法域名”关闭，再做真机登录、拉取、写入和冲突测试。

当前 HTTP IP 地址只用于开发者工具联调，不应作为正式生产配置。

## 7. 发布与回滚检查

- 发布前：运行 `node --test tests/*.test.js`，并在 `server/` 运行 `npm run check`。
- 数据库变更：先备份，再执行向前兼容迁移；不要直接删除生产字段。
- API 更新：保留上一版本目录和环境文件备份，健康检查通过后再切换流量。
- Nginx 更新：备份站点配置，`nginx -t` 成功后 reload。
- 回滚后：检查 API 健康、微信登录、店铺拉取、一次测试写入和数据库 revision。

## 8. 管理后台接入

管理后台与小程序共用同一 MySQL，不另建一套业务数据。Go API 默认监听 `127.0.0.1:3001`，Nginx 将 `/admin-api/` 转发到该服务；后台静态文件部署到 `/var/www/admin/`。

1. 从 `server-go/.env.example` 创建仅服务器可读的管理 API 环境文件，并配置同一 MySQL 账号；商品图片默认保存在 `/var/lib/pingping-admin-api/product-images/`。
2. 执行到 `007_admin_product_code_sequence.sql`，创建独立后台账号、角色、权限、业务流水、基础设置、审计表和后台商品编号序列表。
3. 构建并启动 `server-go/systemd/pingping-admin-api.service`，检查 `/admin-api/v1/health`。
4. 在 `admin/` 执行 `pnpm build`，将 `dist/` 发布到 `/var/www/admin/`。
5. 登录后应验证员工列表、权限变更和退出登录；生产首次登录后建议立即重置初始化密码。

发布和回滚时应将商品图片目录与 MySQL、后台静态文件和 Go 二进制一起备份；图片目录由 systemd 的 `StateDirectory=pingping-admin-api` 创建并授权给服务账号。

浏览器会话与微信令牌完全独立；退出登录会删除服务端会话，停用员工后该账号不能创建新会话。
