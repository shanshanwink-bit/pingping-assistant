# 萍萍小助手

供单家服装与化妆品门店内部使用的经营助手，包含微信原生小程序、Vue 3 管理后台、Node.js 小程序 API、Go 管理后台 API 和 MySQL 数据库。

## 当前功能边界

小程序负责高频经营操作：

- 首页：今日销售、今日盈利、库存预警和近期记录。
- 商品：服装与化妆品档案、规格库存、搜索、详情和商品维护。
- 卖货与拿货：按真实规格扣减或增加库存，并生成销售、采购和操作记录。
- 账本：销售收入、采购现金支出、其他收入、其他支出和经营盈利。
- 我的：用户资料、同步状态、操作记录、后台地址和退出登录。

小程序底部导航固定为“首页、商品、账本、我的”。卖货、拿货和其他收支从首页、商品详情或账本中的明确入口进入，不再使用独立的 quick-action 页面。

Web 管理后台负责低频管理与核对，最终导航为：经营看板、商品中心、库存中心、销售与收支、经营分析、员工与权限、操作日志。采购与供应商、基础设置未进入最终导航；销售与收支和库存中心以只读核对为主，不与小程序形成第二套高频经营入口。

## 数据与服务

- `server/`：Node.js 18+ 小程序 API，负责微信登录、会话、店铺状态同步、商品目录和原子卖货/拿货事务。
- `server-go/`：Go 1.22+ 管理后台 API，前缀为 `/admin-api/v1`，负责独立后台会话、员工权限、商品管理、经营读取和审计。
- 两个服务使用同一 MySQL 和同一 `storeId`，但使用不同登录会话。
- 小程序经营主数据保存在 `store_states`；后台经营看板、销售与收支和经营分析优先读取其中的 `sales[]`、`purchases[]`、`manualProfits[]`，旧 `admin_sales` 与 `admin_finance_entries` 仅作无小程序经营数据时的兼容来源。
- 后台商品使用 `admin_products` 聚合库存；颜色、尺码等规格库存仍以小程序 `products[].specs[]` 为准，两者不能被理解为同一粒度。

经营盈利统一定义为：有真实成本的销售毛利 + 其他收入 - 其他支出。采购计入现金支出，不从经营盈利中重复扣减；缺少成本的销售收入正常计入，但不伪造毛利。

## 目录

- `pages/`、`custom-tab-bar/`、`assets/`、`styles/`、`utils/`：微信小程序。
- `admin/`：Vue 3 + Vite 管理后台。
- `server/`：Node.js 小程序 API、MySQL 迁移和兼容层。
- `server-go/`：Go 管理后台 API。
- `tests/`：Node 自动化测试。
- `docs/`：产品与部署文档。
- `outputs/`：本地验收截图、原型和历史发布产物，不属于运行源码，也不应加入新的 Git 提交或微信小程序打包。

## 本地验证

需要 Node.js 18+、pnpm、Go 1.22+ 和微信开发者工具。

```bash
node --test tests/*.test.js

cd server
pnpm install
pnpm run check

cd ../admin
pnpm install
pnpm build

cd ../server-go
go test ./...
go build ./...
```

微信小程序使用开发者工具导入仓库根目录。`project.config.json` 的打包忽略规则会排除后台、服务端、文档、测试和 `outputs`；正式预览还应检查首页、商品、账本、我的、卖货、拿货和商品详情，不向生产数据库提交测试交易。

## 数据库迁移

迁移位于 `server/migrations/`，全新环境按 `001` 至 `007` 顺序执行。不要修改已经执行过的历史迁移。

`002_admin_mvp.sql` 含早期后台原型数据，`003_admin_auth_permissions.sql` 含初始化后台账号。全新正式环境迁移完成后，必须在开放访问前核对并清理原型行、重置初始化账号密码；不得把历史示例数据当作真实经营数据。

## 当前部署前提

当前小程序 API 与后台地址仍使用备案前的 HTTP 裸 IP 联调配置。正式发布前必须完成域名备案、HTTPS、微信 request 合法域名、正式后台地址、服务器端 Go 构建验证、数据库备份和首次管理员密码重置。部署步骤见[自有云服务器部署说明](docs/guides/自有云服务器部署说明.md)。

真实 AppSecret、数据库密码、JWT 密钥、私钥和生产环境文件不得写入仓库。`.env`、微信开发者工具私有配置、构建产物和新生成的 `outputs` 已由 `.gitignore` 排除。
