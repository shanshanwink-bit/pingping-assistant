# 使用方法
# 以下每一段分别粘贴到同一个 Stitch Web/Desktop 项目的对话中，一次生成一个页面。

【页面 2：商品中心】
延续经营看板设计系统，生成“商品中心 / 商品档案”。标题“48 个商品正在销售”，副文案“集中维护商品资料、规格和状态”。右侧操作“导入商品”和主按钮“＋ 新建商品”。指标摘要：在售 48、服装 32、化妆品 16、资料待完善 4。筛选栏包含全局商品搜索、业务类型、分类、库存状态、商品状态和导出。表格列：商品、编号/货号、业务类型、分类、规格数、库存、参考售价、状态、最近更新、操作。示例包含针织开衫、水洗直筒牛仔裤、水润修护精华液、轻透防晒霜。行操作为“编辑”和更多菜单；不要直接放永久删除。

【页面 3：商品编辑抽屉】
在商品中心右侧打开宽度约 560px 的“编辑针织开衫”抽屉。分区为基本资料、规格矩阵、价格与库存规则。基本资料包含名称、业务类型、分类、货号、供应商和图片；规格矩阵展示颜色、尺码、库存、状态，但库存字段只读，并提示“库存只能在库存中心通过盘点或修正单变化”。价格区有成本价 58、参考售价 129、低库存阈值 3。底部操作：取消、低强调危险操作“停用商品”、主按钮“保存修改”。有业务记录时不展示永久删除。

【页面 4：库存中心】
生成“库存与盘点”页面，说明“所有库存变化都通过业务流水或修正单完成”。顶部操作“库存修正”和主按钮“＋ 创建盘点单”。页签：实时库存、盘点单 1、库存修正 2、库存流水。指标：当前库存 286 件/48 个商品、低库存规格 3、缺货规格 2、待确认差异 2。筛选栏包含商品规格搜索、业务类型、库存状态和“导出库存快照”。表格列：商品、规格、系统库存、可售库存、库存成本、状态、最近变动、操作。突出针织开衫杏色/M 库存 0 且“盘点差异待确认”。

【页面 5：创建盘点单弹窗】
在库存中心打开居中弹窗“创建盘点单”。字段：盘点范围（全部服装/全部化妆品/指定分类）、盘点名称“8月中旬服装盘点”、说明“核对服装区全部在售商品”。信息提示：“创建后将生成库存基准快照；盘点期间仍可销售，确认差异时会重新校验期间变动。”底部为取消和主按钮“确认创建”。弹窗必须有关闭按钮和键盘焦点样式。

【页面 6：采购与供应商】
生成“采购与供应商 / 拿货记录”。顶部操作“供应商档案”和“＋ 登记拿货”。指标：今日拿货 8 件、今日采购支出 ¥360、本月拿货 126 件、合作供应商 8 家。筛选包含商品/供应商/单号搜索、日期、供应商和导出。表格列：时间/单号、商品与规格、数量、单价、总额、供应商、操作人、状态。示例记录：水润修护精华液透明/30ml，8 件，¥45，合计 ¥360，云朵美妆，萍萍，已入库。

【页面 7：销售与收支】
生成“销售与收支 / 销售记录”。副文案“原始记录保持不变，错误通过作废、退货或冲正处理”。顶部操作“其他收支”和“＋ 登记销售”。筛选为商品/单号/操作人、日期、收款方式和导出。表格列：时间/单号、商品与规格、数量、销售额、成本、毛利、收款方式、操作人、操作。示例牛仔裤销售额 ¥169、成本 ¥72、毛利 ¥97、微信、小周；针织开衫销售额 ¥129、成本 ¥58、毛利 ¥71、现金、萍萍。行操作使用“纠错”，不要使用“编辑历史记录”或“删除”。

【页面 8：经营分析】
生成“经营分析”页面。标题“本月盈利稳步增长”，日期 2026年8月1日至8月15日。筛选包含全部/服装/化妆品、时间、分类；操作为自定义日期和导出报表。指标：销售收入 ¥18,680、已售商品成本 ¥10,892、经营盈利 ¥7,420、毛利率 41.7%。主图为每日收入与盈利趋势；右侧商品盈利排行：牛仔裤、针织开衫、精华液、防晒霜。图表必须有坐标、图例、单位和无数据状态，不要用纯装饰图。

【页面 9：员工与权限】
生成“员工与权限”。标题“4 位成员正在协作”，副文案“角色决定默认权限，个别成员可单独调整”。顶部操作“角色模板”和“＋ 邀请成员”。摘要：店主 1 人、店员 2 人、财务 1 人。表格列：成员、角色、数据范围、关键权限、最近活跃、状态、操作。包含萍萍店主、小周店员、小林财务、小陈已停用。页面下方显示安全提示：“权限由服务端校验；隐藏页面入口不能代替权限控制，成员被停用后新的接口请求会立即被拒绝。”成本、盈利、导出和权限管理需要独立权限项。

【页面 10：基础设置】
生成“基础设置 / 店铺规则”。使用两列设置卡片：商品分类、库存与提醒、收款方式、商品编号。分类展示上衣、裤子、裙子、外套、护肤、彩妆；默认低库存阈值 3 件，临期提醒提前 60 天；收款方式为微信、支付宝、现金、银行卡；编号规则说明“创建后稳定，不重排、不复用”。右上主按钮“保存更改”。设置变更需要展示影响范围，不要把危险清空数据放在此页。

【页面 11：操作日志】
生成“操作日志”。标题“关键变更可追溯”，副文案“记录操作者、来源终端、原因和变更前后值”。筛选包含动作类型、成员、日期范围和导出。时间线或表格至少展示：小周从小程序提交针织开衫杏色/M 库存差异 2→0，待确认；萍萍从管理后台给小林新增报表导出权限，已生效；萍萍停用旧款风衣 0026，历史记录保留。每条显示请求 ID、来源终端、时间和状态。

【全局状态补充】
为表格、图表、抽屉和弹窗补充统一状态：加载骨架、空数据、服务器错误、无权限、筛选无结果、导入处理中、导入部分失败、版本冲突。错误状态必须包含请求 ID 和重试入口；无权限状态不能泄露成本或盈利数据；批量操作显示选中数量和影响范围。

【全局统一修正指令】
统一检查全部管理后台页面：固定侧栏、顶部栏、页面标题区、筛选栏、14px 卡片圆角、表格密度、按钮层级和状态标签必须一致；所有文字为简体中文；把任何“腾讯云开发、云函数、云数据库”改为“自有服务器 API / MySQL”；删除和覆盖历史记录改为停用、作废、退货、冲正或库存修正；确保 1440px、1280px 和 1024px 均可操作且无关键按钮丢失。
